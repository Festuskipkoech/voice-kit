Voicekit Architecture

Voicekit

production voice-agent engine · rust · onnx · llama.cpp · websocket

Flexibility

Trait-based engine abstraction. Swap STT, LLM, or TTS by changing one line in config.toml; no recompile, no code change.

Latency

LLM token stream feeds the TTS in parallel. First audio chunk plays before the LLM finishes generating. Total target: <3 s end-to-end on CPU.

Package Layers

Real-Time Pipeline — one WebSocket session

config.toml selects the provider string at startup. The server holds Box<dyn SttEngine> etc., so a new model ships as a new struct that implements the trait — no changes to the session loop.

Measured Latency Budget (CPU, Ubuntu 24.04)

<10 ms

~376 ms
LLM · Gemma 3 1B Q4
~1578 ms
TTS · Paradee int8
~708 ms
Total (sequential)
~2661 ms
First audio (streamed)
~1100 ms

"First audio" = STT + first LLM sentence + TTS of that sentence. LLM and TTS overlap after that, so the user hears a response before generation completes.

Docker Deployment

# run with default models
docker run -p 8080:8080 \
-v $(pwd)/models:/models:ro \
-v $(pwd)/config.toml:/config.toml:ro \
ghcr.io/voicekit/voicekit-server:latest

voicekit-cli

# pull models (runs once, cached to ./models/)
voicekit pull moonshine-tiny paradee-int8 gemma3-1b-q4

# benchmark all engines on this machine
voicekit bench --config config.toml

# health check a running server
voicekit health ws://localhost:8080
